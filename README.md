# Breeze WebDAV 漫画插件

在 Breeze 里直接看 WebDAV（NAS、自建网盘、rclone serve 等）上的漫画：

- 扫描图片文件夹：目录里只要直接含有 jpg/jpeg/png/webp/gif/bmp，这个目录就算一本漫画；
- 扫描 CBZ/ZIP 整包：只读压缩包尾部索引（EOCD/中央目录），翻到哪页才拉哪页的字节；
- 页序按自然序（p2 在 p10 前）；
- 关键词过滤 + 分页；
- 详情页、阅读快照、按页取原图；
- 错误提示都是中文人话。

当前版本 0.3.0。PDF 不做。

## 在 Breeze 里安装

1. pnpm build，然后在仓库里起静态服务器：

   ~~~bash
   python3 -m http.server 7878 --directory dist
   ~~~

   让手机和电脑在同一局域网，确认 http://<电脑IP>:7878/breeze-plugin-webdav.bundle.cjs 可访问。
2. Breeze → 发现页 → 插件商店 → 浏览安装 → 网络安装，填入上面的 bundle 地址。
3. 进入插件设置，填服务器与扫描参数（见下一节）。
4. 发现页会出现两个入口：
   - **漫画库**：按设置扫描出的漫画列表；
   - **搜索**：Breeze 搜索页，输入关键词过滤漫画名。

   设置页通过 Breeze 的「插件设置」进入，不用单独入口。

## 设置项

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 服务器地址 | 空 | 例如 http://192.168.1.2:5005/dav；不写协议时按 http 补 |
| 用户名 | 空 | Basic 认证用户名；用户名和密码都为空时不发认证头 |
| 密码 | 空 | Basic 认证密码 |
| 漫画库根路径 | / | 相对服务器地址的起点，例如 /comics |
| 扫描深度 | 2 | 根目录算第 0 层；最多向下几层找「没有图片的目录」 |
| 漫画数量上限 | 300 | 一次扫描最多返回多少本，避免大库卡死 |
| 收录 CBZ 整包 | 开 | 关闭后只认图片文件夹 |

扫描规则：

- 目录的直接子项里有图片 → 该目录是一本漫画，**不再向下钻**；
- 目录里没有图片 → 继续向下找，直到扫描深度用完；
- 同级的 .cbz / .zip 文件各自算一本漫画（开关打开时）；
- 关键词只过滤漫画名，大小写不敏感；每页 20 本；
- 同一层的目录并发 4 个（上限 8）列目录，结果顺序仍按服务器返回顺序拼接，和串行完全一致；
- 一次扫描最多发 2000 次 PROPFIND，超过就停止并提示「结果可能不完整」；
- 扫描结果缓存 45 秒，翻页不会重新全量扫描。

## 支持 / 不支持

**支持**

- WebDAV 的 PROPFIND 列目录（通过宿主全局 __http_request_promise 发，标准 fetch 发不出 PROPFIND）；
- Basic 认证、中文 / 空格路径的百分号编码；文件名里的字面 %20 按字面量处理（% 会编码成 %25），不会二次解码；
- 图片文件夹与 CBZ/ZIP；跨站点的绝对 URL 会被拒绝，不会把认证头发到别的 host；
- CBZ 中央目录解析 + 单页流式 inflate；支持 HTTP Range 的服务器上只按需拉单页字节，中央目录在内存里缓存（几十 KB），整包缓存只在回退时使用并按 256 MiB 总预算 LRU 逐出；
- 网盘返回 401/403、PROPFIND 405/501、宿主过旧、请求超时的中文提示。

**不支持**

- PDF（任务范围外）；
- 目录逐级钻进 UI：一本漫画就是「单章全一话」，不提供卷/话树；
- 压缩包加密；ZIP64 结构（条目数达到 65535，或单条目尺寸达到 4 GiB 时判定为 ZIP64）；
- 需要登录页 / Cookie / Token 的网盘，只支持 Basic 认证；
- 修改服务器上的文件（只读）。

## 已知限制

- **单次请求 30 秒硬超时**：宿主对每次 HTTP 请求固定 30 秒超时，插件侧改不了。所以整包下载改成按实测吞吐自适应分块：先用 1 MiB 的 Range 探测量出速率（这段字节直接算第一块），块大小 = 吞吐 × 15 秒，夹在 256 KiB–16 MiB 之间；单块超过 25 秒或失败就先把块减半再重试（同一尺寸不再重试 4 次，避免真实网络白等两分钟），连续两块都快于 3 秒就翻倍。只要自适应生效且文件大于 256 KiB 就一律走分块循环（哪怕只剩一块），因此 ≤16 MiB 的包在慢网上也能靠减半下完。拿不到吞吐（探测失败 / 5xx / 服务器忽略 Range）时按默认 8 MiB。实测 1 Mbps 下 8 MiB 块必超时，自适应会把块压到约 1.8 MiB 并稳定下完。
- **CBZ 按需取页（需要服务器支持 Range）**：先读文件尾部 65557 字节（22 字节 EOCD + 65535 字节注释上限）拿到 EOCD 与中央目录，取某一页时只 Range 拉这一页的本地头与压缩数据，再流式解压。50 MiB 的包单页首屏约 0.95%、5 页约 4.3%，不再整包下载。中央目录（几十 KB）按包缓存在内存里，取下一页不再重读 EOCD。
- **服务器不支持 Range 时自动回退整包**：如果服务器忽略 Range（返回 200）、返回的 Content-Range/长度不对，或尾部窗口里找不到 EOCD（可能是注释超长），插件会按「包 + 原因」记录一次诊断（并发也只记一条），然后回退到整包下载路径（同样按吞吐自适应分块，默认 8 MiB）；200 响应已经带回的整包会先读一遍中央目录自校验，能读出来才进缓存直接复用（不再下载第二次），读不出来就丢弃、不缓存并给明确错误。回退后该包后续取页不再反复试错。整包缓存按 256 MiB 总预算 LRU 逐出，缓存键包含服务器地址和用户名，换账号不会串包。
- **封面也走同一条路径**：列表里的封面是 wdav:// 占位地址，宿主真正加载封面时才去下载；CBZ 封面只拉第一页的字节，不会再触发整包。
- **注释与索引上限**：尾部窗口按 ZIP 规范最大注释（65535 字节）取 65557 字节，恰好 65535 B 的合法注释能正常读。注释字段（u16）本身无法超过 65535；若文件实际在 EOCD 之后还有更多字节导致整包路径也找不到中央目录，会明确报「这不是有效的 CBZ/ZIP 文件」，不会崩溃。中央目录上限 64 MiB、单条目本地头扩展字段上限 1 MiB。ZIP64 结构仍然不支持（明确拒绝）。
- **下载与解压上限**：整包下载最多 256 MiB；远程路径收到 200 整包时若超过 256 MiB，直接报「超过插件下载上限」，不挂缓存、不再二次请求。CBZ 单页解压后最多 65 MiB，压缩数据最多 66 MiB（给 deflate 对不可压数据约 0.02% 的膨胀留余量），压缩比超过 1000:1 视为异常并拒绝；远程取页会在发任何字节请求前先预检这些字段（加密位、解压尺寸、压缩数据尺寸、压缩比），不合规的条目 0 次内容请求就报错。解压采用流式计数，中央目录谎报尺寸也会被中途截断；每一页解压后都校验 CRC32，对不上就报「CRC 校验失败」，不会返回错误字节。
- **拿不到文件长度就不下载**：HEAD 没有 Content-Length 时改用 GET Range 0-0 读 Content-Range；如果服务器忽略 Range 返回 200，这次探测本身可能已经收到整包，整包路径会判定探测失败并停止，不会再把整包当长度结果，也不会再发第二次整包 GET；两样都失败会明确报「服务器不支持分块下载，也拿不到文件长度」。远程取页遇到 200 时则把响应体当作真实整包，直接交给回退路径复用。
- **Range 请求会重试**：5xx / 408 / 429 按 300ms 起指数退避重试 3 次（与整包下载一致）；401/403 不重试，直接给认证错误。
- **并发抓图**：宿主默认并发 5；同一 CBZ 的多个页面共享同一次中央目录读取（in-flight 去重）。远程取页不缓存整页字节；中央目录缓存另有 8 MiB 总预算（最多 16 个包，按 LRU 逐出；预算比单个包还小时连最后一条也会被逐出，下次取页重新读一次索引）；回退整包的包会顺手释放它的中央目录名额；整包缓存按 256 MiB 总字节预算 LRU 逐出，不按整包个数封顶。
- **最坏内存占用**：远程取页时只占单页缓冲（≤65 MiB）与中央目录（几十 KB）。只有服务器不支持 Range、回退整包时才会占用整包缓存预算（256 MiB）+ 在途下载（宿主并发 5 个不同 CBZ 封面时可达 5 × 256 MiB = 1.25 GiB）。内存紧张时少用大 CBZ 或降低宿主并发。
- **根目录必须能列**：rootPath 不存在、无权限或服务器不支持 PROPFIND 时直接报错，不会显示成空库；更深的单个子目录失败只跳过它并计数（scanWarning 提示）。
- **扫描并发**：同一层的目录并发 4 个请求（可配 1-8，测试里用 1 当串行基线）；20 ms 延迟的服务器上首屏约快 3.8 倍。并发只影响「谁先回来」，结果、顺序、maxComics 截断、跳过计数与串行逐项一致；一旦达到 maxComics 就立刻停止，不再把同层剩余目录列完（不会为了截断多花成百上千次 PROPFIND）。扫描并发（4）与宿主取页并发（5）是叠加的，慢 NAS 上最多会有 9 个在飞请求；想更保守可把并发调成 2 或 1。
- **扫描广度上限**：一次扫描最多 2000 次列目录请求；超限会返回已发现结果并附带中文提示。有「无法安全读取」或列目录失败的条目时，提示也会出现在列表响应 extern.scanWarning、详情描述和详情/快照的 extern 里；冷启动直接进详情/阅读器时也会按本次列目录的跳过数补一条，结果可能不完整。
- **只有真实危险的路径会被拒绝**：解码后的路径里含字面反斜杠、.. 段或 NUL/控制字符时，插件不会发这个请求（防目录穿越），只影响那一条/那一本，并提示「这一项的路径不安全，已跳过」。合法文件名（含 %、中文、空格、emoji，甚至字面 %5C / %2e%2e 这种名字）照常能列、能开、能取图。列表与扫描不会因为单个怪名字或单个目录列失败而中断：跳过的条目会计数，scanWarning 给出「有 N 个条目无法安全读取…」，rootPath 外的条目静默忽略。
- **扫描缓存**：同一套设置 45 秒内复用上次结果；刚往网盘加了漫画，最多等 45 秒再刷新。
- **密码明文保存**：密码是普通设置字段，宿主只做遮挡显示，落盘未见加密（与 Breeze 其他插件的设置一致）。
- **PROPFIND 依赖未文档化全局**：__http_request_promise 不是官方文档 API，Breeze 未来若收紧会失效。
- **运行时是 text-encoding polyfill**：Breeze 的 QuickJS 运行时替换了全局 TextDecoder，不支持 `fatal` 选项，传了会在构造时直接抛异常（Node 支持这些选项，普通用例抓不到这类环境差异，必须保留 polyfill 替身用例）。插件只使用不带选项的 UTF-8 解码，非法 UTF-8 由 U+FFFD 检查拒绝；后续维护不要给 TextDecoder/TextEncoder 传 Node 专有选项。测试里的替身见 test/support/polyfill-textdecoder.mjs。
- **图片字节不进宿主 cache**：宿主 cache 单值上限 500 KiB，图片只走模块内 LRU 或直取。

## 构建与测试

~~~bash
pnpm install
pnpm build          # typecheck + 生成 manifest + rspack 打包
pnpm test           # 构建后跑 node:test
node script/e2e-webdav.mjs
~~~

产物是 dist/breeze-plugin-webdav.bundle.cjs（CJS 单文件，依赖全部内联），同时生成根目录 manifest.json。

- script/test-webdav-server.mjs：用 node:http 手写的测试 WebDAV 服务器（Basic 认证、PROPFIND 0/1/infinity、GET/HEAD、Range）；
- script/e2e-webdav.mjs：加载打包产物，分别以 rootPath=/ 和 rootPath=/comics 跑「目录漫画 + CBZ 漫画」完整链路，报告 CBZ 首屏下载字节数，最后输出 E2E PASS，带两组 dir=/cbz=。

## 调试排错

| 现象 | 提示 | 原因 |
| --- | --- | --- |
| 打不开列表 | 网盘用户名或密码不对 | 401/403 |
| 打不开列表 | 这个网盘不支持列目录（PROPFIND），换一个 WebDAV 地址试试 | 405/501，或地址不是 WebDAV 根 |
| 插件完全没反应 | 当前 Breeze 版本太旧，插件用不了 | 没有 __http_request_promise |
| 图片转圈后失败 | 网盘太慢或文件太大，下载超时 | 宿主 30 秒总超时 |
